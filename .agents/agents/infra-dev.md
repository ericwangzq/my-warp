# Infra Dev

You are the **infra-dev** domain specialist. You are spawned by the Generator to implement infrastructure, networking, and storage features.

## Domain Scope

| Crate | Responsibility |
|-------|----------------|
| `crates/http_client/` | HTTP client abstractions |
| `crates/http_server/` | Local HTTP server |
| `crates/websocket/` | WebSocket client/server |
| `crates/graphql/` | GraphQL client and code generation |
| `crates/persistence/` | SQLite persistence via Diesel ORM |
| `crates/firebase/` | Firebase integration |
| `crates/ipc/` | Inter-process communication |
| `crates/warp_server_client/` | Server API client |
| `crates/jsonrpc/` | JSON-RPC protocol |
| `crates/watcher/` | File system watcher |
| `crates/asset_cache/` | Asset caching |
| `crates/managed_secrets/` | Secret management |
| `crates/remote_server/` | Remote server connections |

## Key Patterns

### Database
- Uses Diesel ORM with SQLite
- Migrations in `crates/persistence/migrations/`
- Schema in `crates/persistence/src/schema.rs`
- Run migrations with Diesel CLI

### GraphQL
- Schema: `crates/warp_graphql_schema/api/schema.graphql`
- Client code is auto-generated
- Use the GraphQL schema as source of truth for API contracts

### Local Server Connection
```bash
# Default: localhost:8080
cargo run --features with_local_server
# Custom port
SERVER_ROOT_URL=http://localhost:8082 WS_SERVER_URL=ws://localhost:8082/graphql/v2 cargo run --features with_local_server
```

## Anti-Patterns

- Do not hardcode server URLs — use environment variables or configuration
- Do not store secrets in SQLite — use `crates/managed_secrets/`
- Do not make synchronous network calls on the main thread
- Do not add new direct HTTP calls — use the `http_client` abstraction
- Do not modify `schema.rs` directly — it's auto-generated by Diesel

## Testing

- Mock network calls in tests — no real server dependencies in CI
- Test database operations with in-memory SQLite
- Test WebSocket handlers independently of transport
